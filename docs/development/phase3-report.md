# Phase 3 報告（2026-11-12）

Phase 3（レンダラーの完成と HDRP からの独立）の結果です。

**結論：HDRP を生成せずに、Aether だけでゲームの画面を描く構成が既定になりました（ガレージで確認）。** ただし確認はガレージのシーンだけです。コース（走行中）はまだ見ていません。純正と同等と言えるのはガレージの絵までで、下の「未実装・未確認」に挙げた差が残っています。したがって **Phase 3 を「完全に完了」とは書きません。**

D3D12 の破損でクラッシュする問題は、ANZU の動画広告が原因としてクローズしました（2026-11-12、所有者の判断。`stability-investigation.md` の 10 章）。DX12 で動画を止める対処は残します。今回の作業中（ガレージとロビー、数十回の起動）に、この問題によるクラッシュは起きていません。

区分：**[ゲーム]** ゲーム内で確認／**[ホスト]** テストホストで確認／**[実装]** コードのみ（動作未確認）／**[未]** 未実装。

## 1. HDRP からの独立

| 項目 | 内容 | 状態 |
|---|---|---|
| 独自のレンダーパイプライン | `AetherPipeline`（Unity の SRP）。レンダーモード `aether`（既定）ではゲームのパイプラインアセットを Aether のものに差し替える。Unity が HDRP のインスタンスを作らないので、HDRP のレンダーターゲット・バッファー・シェーダーは存在しない | [ゲーム] `Player.log` に `HDRenderPipeline` が一度も出ない。HDRP のグローバルテクスチャ（`_SkyTexture` ほか）はすべて null |
| 起動 | 最初のフレームの前に差し替える。HDRP 用の DX12 修正（コンピュートシェーダー 118 本の差し替え）は、HDRP を使うモード（`hdrp` / `compare`）に入るときだけ適用 | [ゲーム] |
| カリング・LOD・スキニング | パイプラインがカメラごとに `context.Cull` を呼ぶ。`Renderer.isVisible`、LOD の選択、GPU スキニングは Unity のまま動く | [ゲーム] |
| 画面外の影キャスター | Unity は画面外のものを教えないので、影を落とすレンダラーは Aether が自分で拾う。LOD グループの段は Unity と同じ規則（画面上の高さ × LOD バイアス）で選ぶ。太陽のカリングマスクに入っていてカメラに映らないレイヤーは「影だけ」として渡す | [ゲーム] ガレージで 306 個 |
| ボリューム（空・露出・トーン・フォグ・ブルームなど） | Unity の VolumeManager を Aether が起動する。HDRP 用のコンポーネント型とゲームの既定プロファイルを読み込ませ、カメラ位置で評価する。カメラごとの機能スイッチ（フレーム設定）もデータとして読む | [ゲーム] |
| 空 | ゲームの HDRI 空のキューブマップをそのまま使う（強度 = 2^exposure / 1.2、回転は −rotation。HDRP と同じ式）。拡散の環境光は、空をコサインで畳み込んだ放射照度マップを毎フレーム自前で作る | [ゲーム] HDRI 以外の空（物理ベースの空など）は未対応 |
| 露出 | 自前の測光（HDRP と同じ式と上下限）。ガレージでは純正と同じ値（EV 2.05）になることを確認 | [ゲーム] 測光の重みは一様（HDRP は中央重点） |
| UI | カメラ用キャンバス（UI レイヤー）は SRP の `DrawRenderers` で、オーバーレイのキャンバスは Unity が描く | [ゲーム] |
| 純正との切り替え | `set_render_mode mode=hdrp` で実行中に純正へ戻せる（比較と計測のため。フォールバックではない） | [ゲーム] |

依存の一覧と残りは `docs/architecture/hdrp-independence.md`。

## 2. 絵の修正（純正と並べて原因を特定したもの）

同じ視点（開発用のカメラ固定 `dev-camera.txt`）で純正と Aether を撮り、点ごとに数値で比べました。

| 症状 | 原因 | 対処 | 状態 |
|---|---|---|---|
| 全体が明るく白っぽい | トーンカーブの引数の取り違え。HDRP の Shoulder Strength（0〜1）と Shoulder Length（F ストップ）を逆に使い、白飛び点が 6.2 でなく 1.2 になっていた | HDRP の定義に合わせた | [ゲーム] |
| 影の中が明るい | ガレージのスポットライト 4 灯を点けていた。純正では `HDAdditionalLightData` が無効で消灯している | そのコンポーネントが無効なライトは使わない。調光と距離フェードも読む | [ゲーム] |
| ホイールが白い | リムの色・金属度・粗さはレンダラーごとの `MaterialPropertyBlock` にあり、`_BaseColor` しか読んでいなかった | すべてのプロパティをブロック優先で読む。毎スキャン再変換し、変わったものだけ送る | [ゲーム] |
| ステッカー・リバリーが出ない | 同上（ボディの `_BaseMap` がリバリー。ブロックで渡される） | 塗装の上にリバリーをアルファで重ねる | [ゲーム] リバリー付きの車で確認 |
| パーツの輪郭が白い | 継ぎ目の帯（`CarPaintStitches`）を不透明の白で描いていた | パックテクスチャの B を不透明度に使う（係数は目合わせ） | [ゲーム] 純正よりまだ少し目立つ |
| 車の下が明るい | ゲームのブロブシャドウ（箱型のデカール）を描いていなかった | 深度から位置を復元して暗くするデカールパス | [ゲーム] 純正より範囲が狭い |
| 一部の物体が出ない | 実行時に作られるメッシュ（初見時は頂点 0）を「非対応」と確定していた | 動的メッシュとして追跡し、中身が変わるたびに登録し直す | [ゲーム] 登録は確認。タイヤ痕などコースでの表示は未確認 |
| 頂点が暴れる（報告） | スキンメッシュは Unity の GPU スキニングの出力を借りている。Unity が複数のバッファーを交互に使う場合、スキャン間隔の間は前フレームの頂点を描く | 毎フレーム、そのフレームのバッファーを確かめて切り替える | [実装] ガレージでは交互にならず、再現も検証もできていない |
| 輪郭のギザギザ | アンチエイリアスが無かった | TAA | [ゲーム] |

残っている数値の差（露出を純正と同じ値に固定した比較、ガレージ）：タイヤ・ヘッドライト・影の中は ±5%、日なたの塗装は +18〜30%、リム +50%、日なたのアスファルト −28%。照明モデルは HDRP の流儀（Burley 拡散、粗い面の反射方向、プローブのミップ選択）に合わせましたが、完全には一致していません。

## 4. 性能

| 項目 | 内容 | 状態 |
|---|---|---|
| GPU インスタンシング | メッシュ・サブメッシュ・マテリアルが同じ連続したドローを 1 回にまとめる（インスタンスマップ経由） | [ゲーム] ガレージで 966 → 700 ドロー |

計測（ガレージ、1920×1080、RTX 4070 Ti、VSync オフ、15 秒、各 2 回）：

| 構成 | 平均 FPS | フレーム時間 | 専用 VRAM |
|---|---|---|---|
| 純正（HDRP のみ、`hdrp` モードで起動） | 207〜213 | 4.69〜4.84 ms | 1,860 MB |
| Aether（HDRP を生成しない、`aether` モードで起動） | 326〜369 | 2.71〜3.06 ms | 1,439〜1,442 MB |

Aether が持つ GPU メモリは約 105 MB（うち影のアトラス 64 MB）。機能は同等ではありません（Aether に無いもの：SSR、ボリュメトリックフォグ、パーティクル、コンタクトシャドウ）。以前の「HDRP も動かしたまま Aether を重ねる」構成と「HDRP を待機させる」構成は廃止したので、その数字はありません。

## 5. 未実装・未確認

- **コースでの確認が一切できていません**（入力の自動化が無いため）。走行中の TAA / モーションブラー、車のライトの発光、タイヤ痕、スキンメッシュ（サスペンション）、シーン遷移、HDRI 以外の空。
- SSR（純正は有効。塗装やリムの映り込みが純正より明るい一因）。
- パーティクル（`ParticleSystemRenderer`。ガレージに 6 個）。ゲーム独自の GPU パーティクルは HDRP のカスタムパスなので、Aether のパイプラインでは動かない。
- ボリュメトリックフォグ、コンタクトシャドウ、影の柔らかさ（純正の方が柔らかい）。
- 画面以外に描くカメラ（レンダーテクスチャ向け。ミラーやアイコンがあれば空になる）。
- 鏡面の環境光は空キューブの通常のミップを使う（GGX の事前フィルターではない）。
- 露出の測光は一様（HDRP は中央重点）。
- `_Spectrum`（塗装の効果）、`_MaterialProperties`、タイヤのカスタマイズ（`_TireParams`）は未対応。

## 5.1 ロビーでの確認後の修正（2026-11-12 午後）

ユーザーがロビーで見つけた不具合への対処です。原因はゲーム側のコード（`CarSystems.Runtime.dll`、`Assembly-CSharp.dll` をローカルで逆コンパイルして読んだ）と、同じ視点での純正との比較から特定しました。

| 症状 | 原因 | 対処 | 状態 |
|---|---|---|---|
| 色を変えても反映されない | ゲームは車の部品を組み立てるときにレンダラー全体の `MaterialPropertyBlock` を、色を変えるたびにマテリアルスロット別のブロックを設定する（`CarBodyPart.SetMaterialPropertyBlock`）。Aether はレンダラー全体のブロックを先に読んでいた。`Renderer.HasPropertyBlock` はスロット別のブロックを教えない | スロット別を優先（Unity と同じ順）。`HasPropertyBlock` に頼らず毎スキャン確かめる | [実装] スロット別のブロックが読めていることは survey で確認。色変更そのものは入力が要るので未確認 |
| リバリーが点滅する | 使用中のテクスチャを Unity のマテリアル自身のプロパティから数えていたので、ブロックにしか無いリバリーが 0.5 秒ごとのスキャンで破棄・再登録されていた | 送ったマテリアル記述が名指すテクスチャを数える | [実装] 未確認（リバリー付きの車への切り替えが要る） |
| 部品の輪郭が白い | 継ぎ目の帯（`CarPaintStitches`）のマテリアルは既定で白く、ゲームはこのレンダラーにブロックを渡さない。塗装として描くと白い線になる。純正の絵（同じ視点）では日陰でも暗い溝 | 光を吸う溝として描く（濃さは目合わせ） | [ゲーム] 同じ視点で純正と比較 |
| F10 メニューの後ろがクリックされる | ゲームの入力は Rewired が生入力から読む。ウィンドウメッセージを止めても届く | オーバーレイがマウス／キーボードを使う間、Rewired のマウス／キーボードを無効にする（リフレクション。`GameInputBlock`） | [実装] 未確認（入力が要る） |
| 露出が点滅して見える | 毎フレーム 256 点の測光をそのまま使っていた | 測光点を 576 点（各 4 画素の平均）にし、前フレームの値から時定数 0.5 秒で追従 | [ゲーム] 静止画面で連続 4 フレームの平均輝度が ±1% 以内。動きのある場面は未確認 |
| 車体の横に水平の線が入る（「反射に四角い箱」） | 車の下のブロブシャドウを箱型のデカールで描いていて、箱の中に入る車体の下半分（ドア下部、タイヤ）まで暗くしていた。線は箱の上面の高さ | 箱の上方向を向いた面（地面）だけを暗くする。面の向きは深度の傾きから求める | [ゲーム] 同じ視点で純正と比較 |
| 人や旗が地面にめり込む | スキンメッシュの頂点に `Renderer.localToWorldMatrix`（レンダラー自身のトランスフォーム）を掛けていた。Unity のスキニング結果はルートボーンの空間にある。計測（survey の `skinned`）：Unity 自身のワールド境界は、ローカル境界をルートボーンの行列（布はスケール抜き）で変換したものと一致し、レンダラーの行列では人が 0.87 m 低い | スキンメッシュはルートボーンの行列、布はその位置と回転だけ（`SceneCapture.SkinnedMatrix`） | [ゲーム] 座っている人と旗を同じ視点で純正と比較。ルートボーンのスケールが 100 のドライバーは非表示で未確認 |
| ウィンドウの大きさを変えると真っ暗 | レンダーターゲットのビューが 64 個しかなく、大きさが変わるたびに古い大きさのテクスチャが 120 フレーム残って枯渇（`No free render target`）。続く例外で Aether がそのセッションの描画を止めていた | ビューを 512 個に。テクスチャを新しく作ったフレームでは、2 フレーム使われていないものをすぐ手放す。ビューが取れないフレームは描画を見送る（例外にしない） | [ゲーム] ウィンドウを 60 段階に連続で変えてエラー 0、絵が出ることをキャプチャで確認 |
| 色の変更が遅れて反映される | 変更を 0.5 秒ごとのスキャンでしか見ていなかった | ブロックを持つマテリアルは、ゲームが実行中に変える値（色、粗さ、金属度、クリアコート、ライトの点灯、リバリー）だけ毎フレーム比べ、変わったら変換し直す | [実装] 未確認（入力が要る） |
| キャプチャが失敗する幅がある | 読み戻しバッファーの Map 範囲が、行の詰め物の分だけバッファーの終わりを越えていた（幅が 64 の倍数でないとき） | 範囲をバッファーの大きさに収める | [ゲーム] 3229×1764 で確認 |

## 5.2 コースでのカクつき（2026-11-12 午後）

コース（レンダラー 7,479 個、LOD グループ 2,350 個。ガレージの約 10 倍）で、周期的にフレームが落ちた。GPU は Aether の全パスで約 5 ms と軽く、原因はメインスレッドのシーン取り込みだった（`get_status` の `managed.sceneCapture` に出る `main thread ms` で計測）。

| 処理 | 修正前 | 修正後 | 対処 |
|---|---|---|---|
| フレームの送出（毎フレーム） | 平均 8.0 ms | 平均 2.6 ms | 動かないレンダラー（スキンメッシュでなく、Rigidbody / Animator の下になく、前回から動いていないもの）は、有効状態・影の設定・行列を 0.5 秒ごとの値で済ませる。LOD グループの位置と大きさも読み取り済みの値で計算する |
| 走査 | 最大 10.2 ms（0.5 秒ごと） | 最大 3.2 ms（2 秒ごと、4 フレームに分割） | 既知のレンダラーは毎フレーム約 1/30 ずつ調べ直す。新規レンダラーの探索は 4 段階に分け、2,000 個を超えるシーンでは 2 秒ごと |

フレーム時間（同じコース、3841×2055、VSync 60 fps、12 秒）：

| 構成 | 中央値 | 上位 5% | 上位 1% | 最大 | 下位 1% の fps |
|---|---|---|---|---|---|
| Aether（修正前） | 16.4 ms | 24〜28 ms | 31〜39 ms | 32〜47 ms | 5.5〜24 |
| Aether（修正後） | 16.5 ms | 18.6〜20.3 ms | 27.3〜27.8 ms | 28〜33 ms | 31.9〜36.0 |
| 純正（`hdrp` モード） | 16.6 ms | 18.3 ms | 19.8 ms | 30.3 ms | 35.9 |

**残り**：上位 1% のフレームは純正より約 8 ms 遅い。毎フレームの送出に残る 2.6 ms の大半は、全レンダラーへの `Renderer.isVisible` の問い合わせと見ている（未計測）。これを無くすには、動かないレンダラーの LOD の選択とカリングを Aether 側だけで行う必要がある（Unity のオクルージョンカリングの結果は使えなくなる）。

副作用：スクリプトだけで動かされる物体は動き始めの最大 0.5 秒だけ追従が遅れる。コースでは新しく現れた物体の表示が最大 2 秒遅れる。

## 5.3 残っていた機能の実装（2026-11-12 夕方）

先に、動いているゲームのデータで「純正が実際に使っているか」を確かめた（ガレージ、ロビー、コース Parking）。

| 項目 | 結果 | 状態 |
|---|---|---|
| ゲームの画質オプション（AA の方式、LOD バイアス、異方性フィルター、VSync） | ゲームは `HDRP.MasterVolumes.OnBeginCameraRendering` で HDRP のカメラのボリュームスタックから毎フレーム適用していた。HDRP が無いと何も適用されず、カメラの AA は None のまま（TAA が働いたのは、一度 `hdrp` モードを通ったカメラだけ）。Aether が自分のスタックから同じ値を適用する（`HostQualitySettings`） | [ゲーム] ロビーで「antialiasing mode 2, LOD bias 2.80, anisotropic level 9」が適用され、TAA のパスが動くことを確認 |
| SSR | 不透明パスに 2 枚目の出力（法線・映す層の粗さ・その重み）を足し、別パスで深度をたどって前フレームの絵（TAA の履歴）から映り込みを取る。すでに入っている空 / プローブの反射との差を加算する。対象はホストの設定どおり（滑らかさ 0.9 以上）。TAA が無いフレームは働かない | [ゲーム] ロビーで有り / 無し / 純正を同じ視点で比較。サイドミラーの映り込みが純正と同じ向きに変わることを確認。金属の色付きの反射は重みを明るさ 1 値で持つので色が薄くなる |
| パーティクル（Unity の ParticleSystem） | 生きている粒を CPU で読み、カメラを向く四角形としてネイティブのパーティクルパスで描く（ビルボードと引き伸ばしビルボード。テクスチャシートは「寿命で 1 巡」だけ）。メッシュ型とトレイルは未対応 | [実装] ロビーでは粒が 0 個で、絵は未確認 |
| タイヤスモーク | ゲームのスモークはコンピュートシェーダー（DX12 のカーネルなし）で、DX12 では純正でも出ない。ゲームのエミッター（`TireSmokeGpuEmitter`）は `WheelSmokeGpuSimulation.OnGpuEmissionStep` が呼ばれたときだけ発生データを書くので、Aether がそのイベントを毎フレーム起こして、発生位置・数・色・不透明度をもらう。煙の動き（広がり、上昇、消え方）はゲームのコードから読めないので Aether 独自のモデル（数値は目分量） | [実装] エミッターの設定を読めたことはログで確認。走行中の絵は未確認 |
| コンタクトシャドウ | ゲームのボリュームで有効化されておらず、パイプライン設定でも画面空間シャドウが無効。純正に無い | 不要 |
| ボリュメトリックフォグ | フォグは有効だが、太陽が対象外（`affectsVolumetric` false、dimmer 0）。昼の見た目は高さフォグとほぼ同じはず | 未実装（差が見えるコースがあれば対応） |

## 5.4 走行中の残像とスパイク（2026-11-12 夕方）

| 症状 | 原因 | 対処 | 状態 |
|---|---|---|---|
| ドリフト中に車全体がぶれる（TAA） | 動く物体の画素で、前フレームの同じ画面位置の絵を混ぜていた | 不透明パスの 3 枚目の出力に、物体ごとの画面上の移動量（前フレームのワールド行列と前フレームのカメラから）を書き、TAA はそれで前フレームの位置をたどる。縁では周囲 3×3 で最も手前の面の移動量を使う | [ゲーム] モーションブラーを切った状態で、ドリフト中の車が鮮明なことをキャプチャで確認 |
| 車の輪郭に沿って跡が残る（TAA。「TAA のみ」「モーションブラーのみ」の切り替えで TAA と確定） | 車が通り過ぎた路面の画素の履歴には車が写っていて、色の範囲で絞るだけでは一部が通り抜けた | 履歴（R16G16B16A16F に変更）のアルファに「自分で動く物だったか」を残し、いまの画素と食い違う履歴は使わない。モーションブラーは TAA の履歴に依存しないようにした | [ゲーム] ユーザーが走行中に「残像がほとんど出ない」ことを確認。AA の方式は TAA のままとする（FXAA / SMAA は未実装。ゲームの設定で FXAA / SMAA を選んでも TAA として扱う） |
| モーションブラーが自分の車をぼかす | 車を除外するマスクを色バッファのアルファに書いていたが、色バッファ（R11G11B10）にアルファは無く、常に 1 と読めていた。マスクを画面に表示して、車の形がどこにも無いことを確認 | マスクを移動量の出力の z に持たせる（R16G16B16A16F）。「動く物体」の判定も、直近 45 フレーム以内に行列が変わったもの、に変更（物理の更新が入らない描画フレームがある） | [ゲーム] ユーザーが走行中に車体のぼけが消えたことを確認 |

## 5.5 Aether 自身の画質設定（2026-11-12 夜）

方針：HDRP の廃止に合わせて、**ゲームのグラフィックス設定メニューは読まない**。画質の設定は Aether の設定（`aether.json`）に持ち、F10 のオーバーレイの Settings タブ（「Graphics」）で変える。MCP の `set_render_feature` / 設定の変更も同じ入口を通る。

| 設定 | 既定 | 内容 |
|---|---|---|
| `antialiasing` | on | TAA。ゲームのメニューやカメラの AA の方式は見ない |
| `shadows`、`ssao`、`ssr`、`bloom`、`motionBlur`、`particles` | on | 各機能のスイッチ |
| `shadowSoftness` | 1.5 | 太陽の影の縁をぼかす幅（シャドウマップのテクセル数。0 = 硬い） |
| `motionBlurStrength`、`bloomStrength` | 1.0 | シーンが指定する強さへの倍率 |
| `smokeOpacity` | 1.0 | タイヤスモークの不透明度の倍率 |
| `exposureEV` | 0 | 露出の補正（段） |
| `lodBias` | 2.8 | Unity の LOD バイアス |
| `anisotropicLevel` | 9 | 異方性フィルター |
| `vsync` | 1 | 垂直同期（0 切、1 毎回、2 1 回おき） |

- ゲームのメニューから来る値（`HDRP.Scalability` のボリュームコンポーネント）は読まなくなった。5.3 で入れた「ゲームの画質オプションを適用する」処理は、Aether の設定を適用する処理に置き換えた（`HostQualitySettings`）。
- **読み続けているもの**：コースごとの絵作りのデータ（空、露出の範囲、トーンカーブ、フォグ、ブルームやモーションブラーの強さ、SSR の条件、AO）と、カメラのフレーム設定。これらはユーザーの設定ではなくシーンのデータ。
- ゲーム側のメニュー項目は残っている（消していない）。スモークの発生量と不透明度のうち、ゲームのエミッターが自分で読む分（`GraphicsQuality.smokeLevel` など）は、ゲームのメニューの値がそのまま効く。
- ガラス：映り込みを不透明度と一緒にアルファブレンドに通していて、数 % しか出ていなかった。映り込みはそのまま加わるようにし、反射率は純正の同じ視点の絵に目で合わせた。 [ゲーム] ロビーで比較
- 影：純正の方向光のフィルター品質は Low で Aether と同等。ロビーの同じ視点の比較では、地面の明るさと影の見え方に大きな差は無かった。柔らかさは `shadowSoftness` で変えられる。 [ゲーム]

## 6. 開発用の道具（今回追加）

- `dev-camera.txt`（設定フォルダー）：`px py pz tx ty tz [fov]` で画面カメラを固定。純正と Aether を同じ視点で比べる。ファイルが無ければ何もしない。
- `get_material_info detail=survey` に追加：`volumes`、`propertyBlocks`、`transparentMaterials`、`screenProbes`（画面上の点の下にあるマテリアルの値）、ライトの位置と HDRP 用データ、`hostExposureMultiplier`（純正の露出の実測値）。
- デバッグ表示 `reflection`（空と反射プローブの映り込みのみ）。
- シェーダーのホットリロード（`reload_shader`）で、露出の固定などの一時的な実験ができる。**自動露出が明るさの差を打ち消すので、明るさの比較は露出を固定して行うこと。**
