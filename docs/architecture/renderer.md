# レンダラー

Aether のレンダラーの構造（コマンドリストの単位、レンダーグラフ、フレームのパス、バインディング、ライティングの骨組み、影）をまとめます。
空、雲、ペイント、反射、GI、スモーク、レンズフレアなど個々の描画機能の中身は [rendering-features.md](rendering-features.md) にあります。
デバイスとキューの扱い、完了の判定は [dx12-integration.md](dx12-integration.md)、メモリとディスクリプターは [gpu-resources.md](gpu-resources.md)。

## 構成

| 部品 | ファイル | 役割 |
|---|---|---|
| `Renderer` | `src/Aether.Native/Renderer/Renderer.{h,cpp}` | ホストのイベントごとにコマンドリストを 1 本記録して提出する。リストの再利用、完了マーカー、GPU タイムスタンプ、フレームキャプチャ、障害時の停止 |
| `SceneRenderer` | `Renderer/SceneRenderer.{h,cpp}` | シーンの 1 フレーム。描画リスト、カスケード、ライトのクラスター、フレーム定数を作り、パスをレンダーグラフに登録して実行する |
| `RenderGraph` | `Renderer/RenderGraph.{h,cpp}` | パスとリソースの宣言、検証、一時テクスチャーの割り当て、状態遷移、実行 |
| `GpuTimer` | `Renderer/GpuTimer.{h,cpp}` | シーンのパスごとの GPU 時間 |
| `SceneBvh` | `Renderer/Bvh.{h,cpp}` | シェーダーで光線を飛ばすための三角形の BVH（DXR は使わない） |
| スモーク | `Renderer/Smoke.cpp` | タイヤスモークのパフの移動（`Aether_SmokeStep`）と、パーティクルパス用の四角形 |
| `ShaderManager` | `Shaders/ShaderManager.{h,cpp}` | `shaders/*.hlsl` を実行時に DXC（シェーダーモデル 6.5）でコンパイルする。DXR 1.1 の無い GPU では `AE_NO_RAYS` を付け、光線は何にも当たらない |

シーンのシェーダーは `shaders/aether_scene.hlsli`（共通の定義、レジスター）、`scene_forward.hlsl`（メッシュのパス）、`scene_post.hlsl`（全画面パス）、`scene_particles.hlsl`（パーティクル）、`aether_bvh.hlsli`（BVH の走査）です。
コンパイルエラーはデータとして残ります（オーバーレイの Shaders、MCP の `get_shader_errors`）。シーンの必須シェーダーが 1 つでも失敗すると、直るまでシーンは描かれません（`E_SCENE_SHADERS`）。パーティクルのシェーダーだけが失敗した場合はパーティクルが出ないだけです。`reload_shader` で再起動せずに読み直せます。

## コマンドリストの単位

`Renderer` はホストの描画イベントごとに 1 本のリストを記録します。

| イベント | リスト | 内容 |
|---|---|---|
| `FRAME_BEGIN` | タイムスタンプ 1 個 | フレーム全体の GPU 時間の起点（設定 `gpuTiming`） |
| `SCENE` | シーンの 1 フレーム | `SceneRenderer::Render` が記録する全パス。最後に `Composite` がバックバッファーへ書く |
| `FRAME_END` | フレーム末尾 | `TestTriangle`（設定 `testTriangle`）、`Overlay`（Dear ImGui）、`FrameCapture`（要求があったときだけバックバッファーを読み戻して PNG にする）と、タイムスタンプの解決 |

- どのリストも最後に完了マーカーを書きます（[dx12-integration.md](dx12-integration.md) の「完了の判定」）。
- `FRAME_END` で何も描かず GPU 計測も切ってあるときは、リストを作りません。オーバーレイが非表示のあいだは ImGui のフレームも作りません。
- `FRAME_END` の描画は、ホストが 8 フレーム以上描いてから始めます。
- キャプチャはオーバーレイの前後どちらでも取れます（`withOverlay`）。

## レンダーグラフ

### モデル

1 フレームはパスの並びです。パスは読むリソースと書くリソースを、D3D12 の状態付きで宣言します。

- **リソース**
  - *Imported*：Aether が持ち、フレームをまたいで残るテクスチャー（シャドウアトラス、空の LUT、反射プローブのアトラス、GI プローブ、TAA の履歴、露出）。状態は GPU リソースマネージャーが追跡します。
  - *External*：ホストのリソース（バックバッファー）。グラフは状態を変えません。どのパスも、ホストが渡したときの状態（`RENDER_TARGET`）で使います。
  - *Transient*：1 フレームの中だけのテクスチャー。プールのテクスチャーが割り当てられます。
- **パス**：`AddPass(name, enabled, setup, execute)`。`setup` が `Read(id, state)` / `Write(id, state)` を宣言し、`execute` がコマンドを記録します。`enabled = false` のパスは記述に残り、実行されなかったと報告されます。
- **順序**：パスは追加した順に実行します。グラフは順序を検査するだけで、並べ替えはしません。
- 1 本のコマンドリストがフレーム全体を運びます。

フレームをまたぐ履歴（TAA の履歴、露出）は、2 枚の Imported テクスチャーを交互に使います（今のフレームが書く方と、前のフレームが書いた方）。

### コンパイル

1. 検証。次のどれかがあるとそのフレームは実行しません。理由はログ（`E_RENDER_GRAPH`、回数制限あり）と `get_render_graph` に出ます。
   - 宣言されていないリソースを使う
   - 1 つのパスで同じリソースを 2 回宣言する
   - 読みを書き込みの状態で宣言する（またはその逆）
   - ホストのリソースを、渡された状態と違う状態で使う
   - テクスチャーの無い Imported リソースを使う
   - どのパスも書く前に Transient を読む
2. 寿命：各リソースの最初と最後のパス。
3. 割り当て：Transient には、記述（サイズ、形式、用途）が同じで、その寿命のあいだ空いているプールのテクスチャーを当てます。寿命が重ならない 2 つの Transient は 1 枚を共有します（`sharesPhysicalTexture`）。無ければ作ります。作れない、またはレンダーターゲット / 深度のビューが取れないときは、そのフレームを実行しません。

### 実行

各パスの前に、宣言に必要な状態遷移を記録します（`GpuResources::Transition`、状態が同じなら何もしない）。設定 `gpuTiming` が有効なら、パスの前後に GPU タイムスタンプを打ちます（`GpuTimer`）。
パスはドローコール数、三角形数、CPU 時間、メモ（`note`）を報告します。

### 終わり

Transient はプールに戻ります。プールのテクスチャーは 120 フレーム使われなければ退役します。そのフレームでプールに新しいテクスチャーを作った場合（ウィンドウのサイズが変わったときなど）は、使われていないものを 2 フレームで退役させます。
退役はそのフレームのリストの完了番号に対して行います（[gpu-resources.md](gpu-resources.md)）。

## シーンのフレーム

`SceneRenderer::Render` の順序：

1. GPU リソースの回収（`GpuResources::Collect`）と、シーンのパスの GPU 時間の回収。
2. `SceneStore::Apply`：メインスレッドから届いた追加・削除、このフレームのトランスフォーム、ライト、プローブ、パーティクル（何も描かないフレームでも適用する）。
3. フレームのアップロードアリーナを取る（取れなければ描かない）。既定テクスチャーのアップロード、マテリアルのディスクリプターテーブルの更新。
4. シャドウアトラスと反射プローブのテクスチャーの用意、このフレームに描く反射プローブの面を決める。
5. 描画リスト（CPU）。光線用のインスタンスもここで一緒に集め、DXR の構造（BLAS、TLAS）を作る。
6. カスケード（`BuildCascades`）、ライトのクラスター（`BuildClusters`）、フレーム定数と各バッファーのアップロード（`UploadFrameData`）。
7. パスをグラフに登録し、コンパイルして実行する。
8. 提出後に `EndFrame`：タイムスタンプの提出、グラフの終わり、このフレームのディスクリプター範囲を完了番号に対して返す。

### 描画リスト

インスタンスごとに、境界球で視錐台カリングします。視野外でも、影を落とすもの、反射プローブに写るもの、光線が当たりうるもの（BVH が要るとき）は残します。

| リスト | 中身 | 並び |
|---|---|---|
| opaque | 不透明（アルファテスト含む） | 頂点レイアウト、カリング方向、アルファテスト、マテリアル、メッシュのキー順 |
| transparent | ブレンドするマテリアル | 奥から手前（オブジェクト単位） |
| casters | 影を落とすもの（ブレンドと `NoShadow` を除く） | opaque と同じキー |
| decals | ブロブシャドウの箱 | |
| probeItems | 反射プローブに写る、動かない近くのもの（車を除く） | opaque と同じキー |

`DrawItems` は、メッシュ、サブメッシュ、パイプライン、マテリアル、ミラーの有無が同じ連続した項目を 1 回のインスタンス描画にまとめます。各描画は、インスタンスマップ（`g_InstanceMap`）の自分の範囲の先頭をルート定数で受け取ります。
シャドウカスケードの描画では、項目の境界球を、太陽の方向に伸ばしたカスケードの境界球と比べて、届かないものを飛ばします。

### パイプラインステート

- メッシュのパスは (頂点レイアウト, パスの種類, カリング) をキーに、必要になったときに作ってキャッシュします。パスの種類は `kDepth`、`kDepthAlpha`、`kShadow`、`kShadowAlpha`、`kForward`、`kForwardBlend`、`kForwardAdditive`、`kDecal`、`kForwardProbe`。作れなかった組み合わせも記録し、毎回は作り直しません。
- メッシュに無い頂点要素（法線、タンジェント、カラー、UV0）は、スロット 7 の 1 頂点の既定バッファーから、インスタンスごとのステップで与えます。
- Unity のメッシュは表が時計回りです（`FrontCounterClockwise = FALSE`）。
- カメラの深度は reversed Z（クリア 0、`GREATER_EQUAL`）。`Opaque` は深度プリパスの深度を使い、深度を書きません。シャドウマップは通常の Z（クリア 1、`LESS_EQUAL`）です。
- 全画面パスは (種類, 出力形式) をキーにキャッシュします。全画面パスのピクセルシェーダーは `scene_post.hlsl` の 1 つずつのエントリーポイントです（`kFullscreenEntry`）。

### パスの順序

`SceneRenderer.cpp` の `graph_.AddPass` の順です。「条件」の欄で「登録しない」とあるものは、条件を満たさないフレームではグラフに入りません。それ以外は常に登録され、条件を満たさなければ無効（`off`）として残ります。

| パス | 条件 | 内容 |
|---|---|---|
| `ShadowCascades` | カスケードがあるとき | 太陽（夜は月）の影を、アトラスの各カスケードのタイルに描く |
| `DepthPrepass` | 常に | 不透明の深度（`SceneDepth`） |
| `SkyTransmittance` | 物理空で、LUT が未作成のとき（登録しない） | 大気の透過率 LUT |
| `SkyMultipleScattering` | 同上 | 多重散乱 LUT |
| `CloudNoise` | 同上 | 雲の形のもとになるタイリングノイズ |
| `SkyView` | 物理空（登録しない） | カメラのまわりの空（毎フレーム） |
| `SkyClouds` | 物理空で雲があるとき（登録しない） | 雲を含めた空。反射と空の拡散光が読む |
| `SkyViewReady` | 物理空（登録しない） | 描画なし。空の LUT を以降のパスが読む状態にする |
| `SkyIrradiance` | 空があるとき（シーンの空のテクスチャーか物理空） | 空の拡散光（32x32 の八面体マップ） |
| `AmbientOcclusion` | 設定 `ssao` | 深度からの AO。間接光が有効なら前フレームの絵から近くの面の照り返しも集める |
| `AmbientOcclusionBlur` | 同上 | 深度を見たぼかし |
| `GiRays` | プローブグリッド GI（BVH が使えるとき、登録しない） | 各プローブから 64 本の光線 |
| `GiIrradiance` | 同上 | 光線の結果をプローブの放射照度に集める |
| `GiDistance` | 同上 | プローブから見た距離 |
| `GiReady` | 同上 | 描画なし。GI のテクスチャーを読む状態にする |
| `ReflectionProbes` | 設定 `reflectionProbe`（このフレームに描く面があるとき有効） | 反射プローブの面を最大 2 面描く |
| `ReflectionProbeBlur` | 同上 | 粗い面用のぼかしたアトラス |
| `Opaque` | 常に | 不透明の陰影。`SceneColor`、`SceneSurface`（法線、反射の粗さと重み）、`SceneVelocity`（画面上の動き）を同時に書く |
| `ReflectionRays` | 光線の反射が有効なとき（登録しない） | 2x2 画素に 1 本（毎フレーム位置を変える）、半分の解像度で光線を飛ばす |
| `ReflectionDenoise` | `reflectionDenoiser = nrd` で、DXR の光線のとき（登録しない） | コンピュート。NRD の入力を作り、NRD（REBLUR_SPECULAR）を実行し、結果を光線と同じ形式に戻す（`ReflectionDenoiser`） |
| `Reflections` | 画面空間反射か光線の反射が有効なとき（登録しない） | 映り込みを `SceneColor` に足す |
| `Clouds` | 物理空で雲があるとき（登録しない） | カメラから見た雲を半分の解像度でマーチする |
| `Sky` | 常に | 遠方面の全画面三角形で空を描く（物理空なら雲の層を重ねる） |
| `Decals` | ブロブシャドウがあるとき | 箱の中の不透明面を深度から求めて暗くする |
| `Transparent` | ブレンドするものがあるとき | 透明物。加算マテリアルは加算ブレンド |
| `VolumetricFog` | ボリュメトリックフォグが有効なとき（登録しない） | フォグが散乱する光を半分の解像度でマーチする |
| `VolumetricFogApply` | 同上 | フォグを絵に重ねる |
| `Smoke` | タイヤスモークがあるとき（登録しない） | スモークを半分の解像度の専用ターゲットに描く |
| `SmokeApply` | 同上 | スモークを絵に重ねる |
| `Particles` | パーティクルがあるとき | ゲームのパーティクル（スモークを半分の解像度で描いたときはそれを除く） |
| `BvhDebug` | `debugView` が `bvh` で光線が使えるとき | 画素ごとにカメラから光線を飛ばし、当たった形を表示する |
| `TemporalAA` | 設定 `antialiasing`（登録しない） | サブピクセルずらした今のフレームを履歴に混ぜる |
| `MotionBlur` | モーションブラーが有効なとき（登録しない） | 画面上の動きに沿ったぼかし |
| `BloomDown0`〜`BloomDown4` | ブルームかレンズフレアが有効で、64x64 以上のとき（登録しない） | 段階的な縮小 |
| `BloomUp3`〜`BloomUp0` | 同上 | 小さい段から拡大して重ねる |
| `Exposure` | 自動露出のとき | 1x1 のターゲットに測光し、前フレームの値から近づける |
| `LensFlare` | レンズフレアが有効なとき（登録しない） | 縮小した絵からゴーストを作る（半分の解像度） |
| `Composite` | 常に | ブルームとレンズフレアを重ね、露出、シャドウ / ミッドトーン / ハイライトの調整、トーンマッピング、sRGB エンコードをしてバックバッファーへ書く（`albedo` などのデバッグ表示では露出とトーンマッピングを掛けない） |

`renderMode` が `compare` のとき、`Composite` はシザーで画面の右半分だけに書きます（左半分はゲームの HDRP の絵）。

### 主なリソース

| 名前 | 種類 | 形式 |
|---|---|---|
| `SceneColor` | Transient | `R11G11B10_FLOAT` |
| `SceneDepth` | Transient | `R32_TYPELESS`（DSV `D32_FLOAT`、SRV `R32_FLOAT`）、reversed Z |
| `SceneSurface` | Transient | `R16G16B16A16_UNORM` |
| `SceneVelocity` | Transient | `R16G16B16A16_FLOAT` |
| `Scene.ShadowAtlas` | Imported | `R32_TYPELESS`（`D32_FLOAT`）、カスケード 2x2 |
| `Scene.History`（2 枚） | Imported | `R16G16B16A16_FLOAT` |
| `Scene.Exposure`（2 枚） | Imported | `R16_FLOAT`、1x1 |

ほかに AO、反射光線、雲、フォグ、スモーク、モーションブラー、ブルームの各段、レンズフレアの Transient と、空の LUT、空の拡散光、GI、反射プローブの Imported テクスチャーがあります。

## バインディング

シーンのパスはすべて 1 つのルートシグネチャー（`Aether.SceneRoot`、`SceneRenderer::EnsureObjects`）を使います。ディスクリプターヒープはシェーダー可視の CBV/SRV/UAV ヒープ 1 本です（[gpu-resources.md](gpu-resources.md)）。

| ルートパラメーター | 種類 | レジスター | 中身 |
|---|---|---|---|
| 0 | ルート CBV | `b0` | フレーム定数（`FrameConstants`。カメラ、前フレームの行列とジッター、太陽、カスケード、クラスターの分割、SH、露出、フォグ、トーンカーブ、反射プローブ、GI、各パスの設定） |
| 1 | 32 ビット定数 ×4 | `b1` | メッシュのパス：インスタンスマップの先頭、マテリアルの番号、カスケードの番号、フラグ（bit 0 ミラー、bit 1 画面空間 AO を使わない）。全画面パス：そのパスの 4 つの値（`g_PassParams`）。パーティクル：バッチの先頭とフラグ |
| 2〜6 | ルート SRV | `t0`〜`t4` | インスタンス（パーティクルのパスではパーティクル）、マテリアル、ライト、クラスターグリッド、ライトの番号 |
| 7 | テーブル | `space1 t0`〜`t4` | マテリアルのテクスチャー：base、normal、mask、emissive、extra |
| 8 | テーブル（全ステージ） | `space2 t0`〜`t3`、`space4 t0`〜`t8` | フレーム共通：シャドウアトラス、空のキューブ、空の拡散光、AO / 物理空の空（雲込み）、透過率 LUT、多重散乱 LUT、雲のノイズ、反射プローブのアトラス、そのぼかし、その深度、GI の放射照度、GI の距離 |
| 9 | テーブル | `space2 t4`〜`t7` | 全画面パスの入力：主入力、深度、補助 2 つ |
| 10 | テーブル | `space3 t0`〜`t3` | ゲームの反射プローブのキューブ（近い 4 つ） |
| 11 | ルート SRV（頂点） | `t5` | インスタンスマップ（描画ごとのインスタンスの番号） |
| 12〜14 | ルート SRV | `t7`〜`t9` | 光線：三角形のプール、フレームの TLAS、そのインスタンス |
| 15 | ルート SRV | `t10` | 光線が当たったインスタンスとサブメッシュのマテリアルと base テクスチャー |
| 16 | テーブル | `space5 t0`〜 | SRV ヒープ全体（16,384）。光線が当たった面の base テクスチャーを番号で読む |

静的サンプラー：`s0` 異方性 8 ・ラップ、`s1` リニア・クランプ、`s2` 比較（`LESS_EQUAL`、境界は白 = 影なし）、`s3` ポイント・クランプ。

- フレーム共通のテーブルと、全画面パス用のテーブル（4 個 ×64 組）は毎フレーム新しく取り、フレームの終わりに完了番号に対して返します。提出済みの前フレームのリストが古いテーブルを読んでいる可能性があるためです。全画面パス用の最初の 4 組は AO、AO のぼかし、Composite、Exposure の固定です。
- 反射プローブの面を描くときは、AO と反射プローブ自身を外した別のフレーム共通テーブルを使います。
- マテリアルのテーブルはマテリアルごとに `SceneStore` が持ちます。マテリアルが無い、またはテーブルがまだ無い描画は既定テクスチャー（白、平らな法線）のテーブルを使います。
- 何も無いスロットには null ビュー（読むと 0）か既定テクスチャーが入ります。BVH を使わないフレームの BVH のスロットにも有効なアドレスを入れておきます。

## ライティングの骨組み（クラスタードフォワード）

G-buffer は持ちません。不透明のパスが、ピクセルごとにライトを数えて陰影を付けます。`Opaque` が同時に書く `SceneSurface` と `SceneVelocity` は、反射、TAA、モーションブラーのための補助です。

- **太陽**：シーンのディレクショナルライトのうち最も明るいもの。物理空のときは時刻から位置と色を決めます。夜は月が同じ扱いになります（[rendering-features.md](rendering-features.md)）。
- **点光源・スポットライト**：CPU でカメラの視錐台を 16 × 9 × 24 のクラスターに分け（奥行きは対数分割、ニアからファーまで、ファーは最大 500 m）、各ライトの範囲の球がクラスターの箱に触れるかで割り当てます。1 クラスター最大 64 個。ピクセルシェーダーは自分のクラスターのリストをたどります。ヘッドランプのスポットライトは、シェーダーがロービームの形を作るため、広い円錐と 90 m 以上の範囲で割り当てます。
- **ライトレイヤー**：インスタンスのレンダリングレイヤーと、ライトが届くレイヤーのマスクをシェーダーで比べます（太陽も同じ）。
- 陰影のモデル（BRDF、ペイント、クリアコート）、環境光、反射、GI の中身は [rendering-features.md](rendering-features.md)。

## 影（カスケード）

- 影を落とすのは太陽（夜は月）だけです。ライトの「影を落とす」フラグと設定 `shadows` に従います。
- アトラスは `D32_FLOAT` の 2x2 タイル。1 カスケードの辺は `quality` で 1024（low）/ 1536（medium）/ 2048（high）/ 3072（ultra）。サイズが変わったら作り直します。
- カスケード数と距離：ゲームが影の距離とカスケード数を送ってきたときはそれを使います（カスケードは最大 4、low は 2。距離は low で 1/4、medium で 1/2、high / ultra でそのまま）。分割位置もゲームの値を使い、最後のカスケードは影の距離で終わります。送ってこないときは low 2 枚・40 m、medium 3 枚・60 m、high 3 枚・80 m、ultra 3 枚・120 m を、対数 0.8 ・線形 0.2 の分割で使います。距離はカメラのファー面を超えません。
- 各カスケードはスライスの 8 隅を囲む球です。半径を 1/16 m 単位に丸め、ライト空間で中心をテクセル単位に揃えるので、カメラが動いても縁がちらつきません。太陽側へ 250 m までの物体が影を落とします。
- ラスタライズ：深度バイアス 200、スロープスケール 2.0、深度クリップなし（ニア面より手前の物体も影を落とす）、カリングなし。
- 参照：点が収まる最も細かいカスケードを、ワールド座標から選びます（反射プローブの面を描くときも正しいカスケードになる）。サンプル位置を法線方向に 1.5 テクセル分ずらします。比較サンプラーで 3x3 のタップ（設定 `shadowSoftness` が 1.6 テクセルを超えると 5x5）を、`shadowSoftness` の幅に広げます。
- 最後のカスケードより外は影なしです（フェードなしで切れる）。

## 制限

- パスの自動的な並べ替え、使われないパスの削除、非同期コンピュート、複数リストへの分割記録はありません。
- 透明物はオブジェクト単位で並べます（ピクセル単位ではない）。
- 影を落とすライトは太陽（夜は月）だけです。点光源・スポットライトに影はありません。
- 最後のカスケードの外で影が切れます。
- GPU カリングはありません（カリングは CPU）。
